# Discovery Features — Making Knowledge Pop Out

Working doc for designing features that surface node content without the user having to dig. All features are per-galaxy opt-in; existing galaxies look identical until an editor turns something on.

## The framing

"Knowledge pops out and offers itself" points at two distinct problems:

1. **Dormancy.** A node is a sphere with no hint of what's inside. Even on hover/click, the user often doesn't know what's worth opening.
2. **Overwhelm.** With 200 nodes, the eye has no entry point.

Most ideas below address dormancy. A few (filtering, welcome prompt) address wayfinding. Worth keeping the distinction in mind when we pick what to build.

## Idea inventory

### From the user

1. **Random ghost-card rotation.** Every few seconds, a card for a random node fades in as a ghost overlay; user can click to open it fully. Ambient, on-brand for cosmic theme. Risks: distracting, fights for attention. Mitigations: only fire when camera is idle N seconds, position card near the actual node so it doubles as wayfinding, easy dismiss, never two on screen.
2. **Hover ghost-card.** Effectively a styled tooltip. Concern about many-node galaxies is solvable with debounce (~400ms steady hover) and rendering one at a time. Reactive instead of ambient, so lower delight than #1. Build alongside #1 sharing the card component.
3. **AI-generated themes/subjects/areas as clickable filters.** Likely the biggest swing. Shape: an admin job iterates nodes in a galaxy, sends name + description + keywords to Claude, asks for 3–7 cluster topics with member node IDs, stored in new `galaxy_topics` / `node_topics` tables. UI: chip strip across top of the galaxy; click to filter. Cost is bounded (run once per galaxy, re-run on demand). Caveat: existing keywords + auto-clustering already do related work; need to decide whether AI replaces keyword clustering or layers on top.
4. **Show a subset of nodes.** Not a feature on its own; this is the interaction model behind 3, 6, and the chip ideas. Filter dimensions: AI topic, keyword, media type, date range, "has media" toggle.
5. **More descriptive nodes.** Multiple sub-ideas:
   - Persistent labels (node name floating beside sphere, density-aware so far/clustered ones hide).
   - Media-type icon badge on each node (image / video / audio / embed).
   - Thumbnail-on-node — for image nodes, the node IS the thumbnail (textured billboard).
   - Auto-summary at the top of the galaxy: one paragraph generated by Claude.
6. **Welcome prompt.** "Are you looking for X, Y, or Z?" with chips. Pairs with #3 — the chips ARE the AI topics. Free-text "tell me what you want" is a much bigger build (embeddings + semantic search); defer to v2.

### Added during brainstorm

- **Spotlight rotation.** One node always softly pulsing/glowing as "featured this minute." Rotates every 15–30s. Cheap, ambient, no popups. Editor can pin specific nodes as eligible, or pick randomly.
- **Auto-tour / cinematic mode.** A "play" button that slowly flies the camera from node to node, opening each card for a few seconds. Great for kiosk / passive viewing / first-visit onboarding. (Detailed design below.)
- **Editor-curated highlights.** A new `is_featured` flag on nodes. Ghost-card rotation, spotlight, and auto-tour all prefer featured nodes. Lets editors steer without authoring a story.
- **Side-panel grid view.** Optional collapsible right rail showing all nodes as a scrollable card grid alongside the 3D scene. Lets users browse linearly when the mesh is overwhelming. Big feature.
- **Keyword chip strip.** A 1–2 hour MVP of idea 4/6 using data we already have: top 8–12 keywords for the galaxy as filter chips at the top.

## Suggested order to ship

Biggest "pop out" per unit work, lightest first:

1. Media-type badges + persistent labels (toggleable). Half day. Makes the mesh stop looking generic.
2. Keyword chip strip + filter. Half day. Wayfinding using existing data.
3. Ghost-card rotation when idle. Half day. The ambient-discovery feel.
4. AI topics replacing the keyword chips. 2–3 days. The real win.
5. Welcome prompt using AI topics. Half day on top of #4.
6. Spotlight, auto-tour, featured flag. Opportunistic.

Each is a per-galaxy setting.

## Open design questions

- AI topics — OK to call the Anthropic API server-side from PHP? Add `ANTHROPIC_API_KEY` to `config.php`, run on demand from the admin console (not auto on every import).
- Per-galaxy controls — new "Discovery" section in the existing galaxy edit form, or a separate settings page? Lean toward extending the existing form.
- Free-text welcome prompt — defer to v2. Embeddings + semantic search is a separate project.

## Auto-tour — detailed design

This is the only discovery feature we're building right now. Everything else in this doc is held until we see how the tour lands.

**Scope note:** desktop and iPad only for v1. Phones get no Play button and no auto-start. We'll figure out the phone exploration story separately.

### Behavior

- **What plays at each stop.** Open the node's info card. Play media in full: if video, play to its `ended` event; if audio, the same. No timeout cap. The next node only starts after the current node's media has finished.
- **Camera.** Reuse the existing focus-on-click ease-in/ease-out animation between stops; same framing as a click-to-focus.
- **Stop / pause / resume controls.**
  - Click anywhere on the 3D scene → pause and exit tour (user takes over).
  - Click the card itself → open it fully, exit tour.
  - Esc → exit tour.
  - Small overlay with pause / next / previous / exit buttons (video-player style).
  - "Now touring · 3 / 10" indicator with progress bar.
- **Dimming non-current nodes.** Deferred. Not in v1.

### Per-galaxy settings

All gated behind a master toggle. If `tour_enabled = 0`, none of the rest apply.

| Setting | Values | Notes |
|---|---|---|
| `tour_enabled` | bool | Master switch. |
| `tour_start_mode` | `immediate` / `idle` / `manual` | `manual` shows a Play button to visitors. `idle` waits for inactivity. `immediate` starts on page load. |
| `tour_node_selection` | `all` / `accentuated` / `random_n` / `tagged` | `accentuated` reuses the existing `is_accentuated` node flag — no new flag needed. |
| `tour_random_count` | int | Used only when selection = `random_n`. |
| `tour_keyword_ids` | list of keyword IDs | Used only when selection = `tagged`. Editor multi-selects from the galaxy's existing keywords. |

### Schema impact

- New columns on `constellations` table for the scalar settings above.
- New junction table `constellation_tour_keywords (constellation_id, keyword_id)` for the `tagged` selection mode.
- `SCHEMA.sql` is updated. For existing instances, the editor runs an ALTER TABLE block (per the project's no-runtime-migrations rule).

### Frontend architecture

- New module `js/tour.js` exporting a `TourController` class.
- Hooks: existing `TelarisNetwork` for node lookup and camera positioning; node card rendering reused as-is.
- Idle detection: listens to `mousemove`, `click`, `keydown`, `touchstart`, `wheel`. On any input during a tour, exit. For start-on-idle mode, restart the idle timer on each input.
- Media end detection: hooks into the card's `<video>` / `<audio>` elements via `ended` event listener.
- Tour HUD overlay: rendered by `tour.js` into a fixed-position container; styled with existing DaisyUI neutral colors.
- Mobile gating: viewport-width check (`>= 768px` allowed). Below that, the Play button is hidden and auto-start modes no-op.

### Backend changes

- Schema update in `SCHEMA.sql` + an `ALTER TABLE` script for existing data.
- `api/constellations.php` — extend single-constellation read/write to include the new fields and the keyword junction.
- Galaxy edit form in admin — new "Discovery" section with the five settings above. The keyword multi-select is populated from that galaxy's keywords.
- Tour config injected into the page by `inc/main-view.php` as `window.TELARIS_TOUR_CONFIG`, alongside the existing globals. The frontend already has every node's keywords, so `tagged` filtering happens client-side; no new API endpoint needed.

### Resolved details

1. Nodes with no waitable media use `tour_default_dwell` (per-galaxy, default 8s).
2. A node has video XOR audio (project invariant), so no media-conflict logic needed. Play whichever exists; advance on its `ended` event. If neither, use the dwell timer.
3. "Tour all nodes" plays in random order per tour run. A stable index/order may come later.
4. `tour_loop` is a per-galaxy setting (bool).
5. `tour_idle_seconds` is per-galaxy, default 30.
6. Tagged selection uses OR logic across keywords.
7. When `start_mode = immediate` AND the galaxy contains any audio node, the admin form shows a warning that audio playback may be blocked until the user interacts with the page.

### Final per-galaxy settings

| Column | Type | Default | Used when |
|---|---|---|---|
| `tour_enabled` | bool | 0 | always |
| `tour_start_mode` | enum(`immediate`,`idle`,`manual`) | `manual` | `tour_enabled = 1` |
| `tour_idle_seconds` | int | 30 | `start_mode = idle` |
| `tour_node_selection` | enum(`all`,`accentuated`,`random_n`,`tagged`) | `all` | `tour_enabled = 1` |
| `tour_random_count` | int | 10 | `node_selection = random_n` |
| `tour_default_dwell` | int (seconds) | 8 | nodes without video/audio |
| `tour_loop` | bool | 1 | `tour_enabled = 1` |

Plus junction table `constellation_tour_keywords` for `node_selection = tagged`.

## Implementation plan

### Step 1 — Schema

- `SCHEMA.sql`: extend the `constellations` table with the seven new columns above; add the `constellation_tour_keywords` junction table (FKs cascade on delete).
- Provide an `ALTER TABLE` block in this doc for the editor to run on the live DB (project policy: no runtime migrations).

**Verify:** running the ALTER block on a copy of prod boots cleanly; `setup.php` on a fresh DB still works.

### Step 2 — Backend data layer (`inc/db.php`)

- Extend `db_get_constellation` / `db_get_constellations` to return the new fields.
- Extend `db_update_constellation` to accept and persist the new fields.
- New helpers: `db_get_tour_keyword_ids($constellationId)`, `db_set_tour_keyword_ids($constellationId, array $keywordIds)`.
- `db_constellation_has_audio_nodes($constellationId)` for the admin warning.

**Verify:** existing PHPUnit tests still pass; add unit tests for the new helpers.

### Step 3 — API (`api/constellations.php`)

- Single-constellation GET includes tour fields and `tour_keyword_ids`.
- PUT/POST accepts and validates them. Validation: `tour_node_selection` matches enum; numeric fields non-negative; keyword IDs all belong to the same constellation.

**Verify:** roundtrip via curl: `GET → PUT → GET` preserves values.

### Step 4 — Admin galaxy edit form (`admin/index.php`)

- New "Discovery" section in the existing edit form (collapsed by default).
- Master `tour_enabled` toggle. When off, the rest is disabled/hidden.
- Conditional fields (start mode → idle seconds; node selection → random count or keyword multi-select).
- Keyword multi-select populated from `db_get_keywords($constellationId)`.
- Inline warning if `start_mode = immediate` AND `db_constellation_has_audio_nodes` is true.
- Submit handler in the `update_constellation` action wires through to `db_update_constellation` and `db_set_tour_keyword_ids`.

**Verify:** edit a galaxy in admin, toggle each setting, save, reload — values persist.

### Step 5 — Inject config into the page (`inc/bootstrap.php`, `inc/main-view.php`)

- `bootstrap.php` reads tour config from the resolved constellation and assembles a JSON-safe array. For `tagged` mode it resolves keyword IDs to a flat ID list (the frontend matches against keyword IDs already attached to nodes).
- `main-view.php` injects it as `window.TELARIS_TOUR_CONFIG = {...}` next to the existing globals.

**Verify:** view source on a galaxy page shows the config; toggling settings in admin reflects in the next page load.

### Step 6 — Frontend tour controller (`js/tour.js`)

A new ES module exporting `TourController`. Responsibilities:

- Read `window.TELARIS_TOUR_CONFIG`. Bail if `tour_enabled` is false or viewport width < 768px.
- On init, choose tour node set based on `node_selection`:
  - `all` — all nodes in the current view.
  - `accentuated` — nodes with `is_accentuated = 1`.
  - `random_n` — random sample of size `tour_random_count`.
  - `tagged` — nodes whose keyword IDs intersect `tour_keyword_ids` (OR).
- Shuffle the resulting list (Fisher-Yates) on each tour run.
- Start mode handling:
  - `manual` — render Play button in HUD; tour starts on click.
  - `idle` — start `tour_idle_seconds` timer on init; reset on user input; on expiry, start tour.
  - `immediate` — start tour after page is interactive.
- During tour:
  - Camera focus on current node (reuse existing `TelarisNetwork.focusOnNode` or equivalent).
  - Open node info card programmatically.
  - If card has a `<video>` or `<audio>` element, attach `ended` listener; advance on fire.
  - Otherwise schedule a `setTimeout(advance, tour_default_dwell * 1000)`.
  - Render HUD overlay: "Now touring · {i}/{n}" + progress bar + pause/next/prev/exit controls.
- Exit triggers: click on 3D scene background, click on card body (opens it fully), Esc key, exit button.
- On end of list: if `tour_loop`, reshuffle and start over. Else exit.

### Step 7 — Wire it up (`js/main.js`)

- Import `TourController` and instantiate after `TelarisNetwork` is ready.
- Pass references to the network, the card-rendering function, and the camera focus method.

**Verify:** in browser, on a galaxy with `tour_enabled = 1`, manual start works; idle start works; immediate start works; clicking 3D exits; Esc exits; loop works; mobile viewport hides Play button.

### Step 8 — Backup engine (`inc/backup.php`)

- Include `constellation_tour_keywords` rows in the per-galaxy bundle.
- The new `constellations` columns are picked up automatically since the engine reads whole rows; verify by inspecting an export.
- Restore (granular and wipe-all) reinstates them.

**Verify:** export a galaxy with tour configured, import into a fresh DB, check settings + keyword set survived.

### Step 9 — Tests

PHPUnit:
- DB helpers (get/set tour keywords, has-audio-nodes detection).
- API roundtrip for tour fields on a constellation.
- Backup roundtrip preserving tour config.

No frontend test harness exists; tour behavior is verified manually per Step 6/7.

### Step 10 — Docs

- Update `CLAUDE.md` with a short "Auto-tour" subsection under the architecture sections.
- Bump `VERSION`.

### Success criteria

- Editor can enable a tour on a galaxy and pick any of the four node selections; visitors see the tour behave as specified.
- Existing galaxies with `tour_enabled = 0` (the default after migration) are visually and behaviorally unchanged.
- Tours work on desktop and iPad. Phones get no Play button and don't auto-start.
- Backup/restore preserves all tour settings.
- All existing PHPUnit tests still pass; new tests cover the new helpers and roundtrip.
